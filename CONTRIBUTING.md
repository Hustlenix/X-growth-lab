# Contributing to X Growth Lab

Thank you for your interest in contributing! We want to make this the best beginner-friendly resource for understanding X, and we need your help to do that.

## How to Contribute
1. **Report Bugs:** Open an issue for incorrect information or broken links.
2. **Suggest Improvements:** If you have a better way to explain a concept or a new strategy, open an issue or a PR.
3. **Write Documentation:** Help us expand our guides and case studies.
4. **Create Visuals:** We love Mermaid diagrams and clean illustrations.

## Repository Standards
- **Beginner-Friendly:** Always assume the reader is new to the platform. Avoid unexplained jargon.
- **Evidence-Based:** When making claims about the algorithm, try to reference official sources or common community findings.
- **Clean Structure:** Follow the existing Markdown formatting and directory structure.

## Documentation Guidelines
Every major document should include:
- **Introduction:** What the topic is.
- **Core Concepts:** The meat of the explanation.
- **Examples:** Real-world applications.
- **Practical Takeaways:** "What do I do with this info?"
- **Further Reading:** Links to related docs.

## Pull Request Expectations
- Keep PRs focused. One major change or a few small fixes per PR.
- Provide a clear description of what was changed and why.
- Ensure all internal links are functional.
- Respect the project memory and core principles.
